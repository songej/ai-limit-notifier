Release notes

0.3.56 October 4, 2026

  • Localized all three Chrome Web Store screenshots for every supported Store language instead of reusing another locale's artwork.

0.3.55 October 4, 2026

  • No user-facing behavior changed; final release verification now proves that the signed-in checks were performed against the exact Store ZIP being submitted.

0.3.54 October 4, 2026

  • Improved Claude feature-limit accuracy when Cowork reports its own weekly allowance.
  • Added a safer final Store-upload check so a release cannot be submitted while signed-in verification is still pending or incomplete.

0.3.53 October 4, 2026

  • Improved Hindi, Filipino, and Dutch interface localization so ordinary UI labels no longer fall back to English.
  • Strengthened localization QA so translated UI copy cannot silently become stale when the English source changes.

0.3.52 October 4, 2026

  • Added Italian, Traditional Chinese, Vietnamese, Thai, Turkish, Hindi, Polish, Dutch, Filipino, Simplified Chinese, and Russian localization for the extension and Chrome Web Store listings.
  • Expanded market-written Store search copy while keeping the in-extension product identity and runtime behavior unchanged.

0.3.51 October 4, 2026

  • Improved Chrome Web Store discoverability with market-specific titles and regional Spanish/Portuguese search wording, while keeping the in-extension brand unchanged.
  • Simplified the public privacy contact line and stopped attaching diagnostic metadata to the external contact-form URL.

0.3.50 October 4, 2026

  • Simplified the public privacy policy so the same data-handling facts are easier to scan; extension behavior is unchanged.

0.3.49 October 4, 2026

  • No user-facing behavior changed; this release makes Chrome Web Store review inputs harder to drift from the extension that is actually packaged.

0.3.48 October 4, 2026

  • Improved reliability on Chrome 116–123 by recognizing the legacy AbortError shape from request timeouts instead of reporting it as offline.
  • Added regression coverage for ChatGPT accounts that report a weekly usage window in primary_window with no five-hour window.
  • Notification status is re-checked when the options or welcome page regains focus, so a changed Chrome/system permission does not leave stale UI.

0.3.47 October 4, 2026

  • Added a concise Chrome Web Store privacy-form summary for release/submission work; runtime behavior is unchanged.

0.3.46 October 4, 2026

  • Chrome's extension-management card now shows the clean AI Limit Notifier name and a shorter localized summary instead of a long keyword-heavy title and a clipped description.
  • No provider, notification, Continue, permission, storage or usage-tracking behavior changed.

0.3.45 October 4, 2026

  • No user-facing behavior changed; release QA now uses the browser channel Playwright supports for unpacked Chrome extensions instead of relying on branded-Chrome sideload flags.

0.3.44 October 4, 2026

  • No user-facing behavior changed; this release strengthens the checks around the exact Chrome Web Store build and current Stable Chrome.

0.3.43 October 4, 2026

  • ChatGPT no longer shows a false sign-in-needed state when its session endpoint returns meaningful but unfamiliar signed-in data; that case is reported as a changed provider response instead.
  • A one-off ChatGPT usage-token mismatch now refreshes the browser session once and retries the usage request before showing an error.

0.3.42 October 3, 2026

  • Continue no longer treats an old conversation in a background Chrome window as recently used on Chrome 116–120, where the lastAccessed tab timestamp is unavailable.
  • A temporary HTTP 503 now respects the service's Retry-After instruction without being mislabeled or counted as an HTTP 429 rate limit.

0.3.41 October 3, 2026

  • Temporary service failures and HTTP 429 rate limits now keep separate retry histories, so a change between them starts with the correct first retry instead of inheriting an unrelated delay.
  • Damaged saved model-limit state is discarded before reset detection, preventing a false model-limit reset notification after storage corruption.

0.3.40 October 3, 2026

  • Refresh reports success only after the service worker confirms the refresh; a worker failure no longer flashes “Updated just now.”
  • If a settings change cannot be confirmed, the popup reloads the saved setting instead of leaving an optimistic control state behind.
  • Reset timestamps are parsed by their provider field contract, so absolute sentinel values cannot be mistaken for a reset happening now.

0.3.39 October 2, 2026

  • First release.
